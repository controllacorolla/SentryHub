# RA-RADIO: cold re-audit of the radio cluster (PRISM SDR++ receiver + PROWL scanner)

Auditor: fresh session, audit only, no code changed. Branch `claude/project-thread-z1copz` at
`2224432` (commits 5236dbe, 859b8bf, 2224432), diffed against `origin/main`. Inputs read: CLAUDE.md,
device-fix-plan items 14 and 15, device-notes PRISM / PROWL, `plan/briefs/RADIO-report.md`, the full
diff. PoCs are in `plan/briefs/RA-RADIO-poc/`. Run each one as `python3 <poc> <repo>` with
`QT_QPA_PLATFORM=offscreen`.

**Verdict: DO NOT MERGE.** Four new High findings. (1) rtl_tcp's stdout is never read, so after
about 3,400 retunes rtl_tcp stops applying them while IQ keeps flowing. (2) Any non-`SourceError`
exception kills the IQ worker with no status, and the run buttons stay green. (3) Changing the bank
during a priority check crashes the scanner. (4) Max hold does not free the channels that share a
window with a continuous carrier.
The DSP is honest, and the ownership ordering is correct for stop, mid-read revoke and PANIC.

## New findings

| ID | Sev | Finding | PoC / evidence | Where |
|---|---|---|---|---|
| N1 | **High** | **rtl_tcp stdout is never drained, so retunes silently stop after ~3,400 commands.** `Pipeline` gives every stage `stdout=PIPE`. RtlTcpSource reads only stderr. osmocom `rtl_tcp.c` `printf`s `"set freq %d"` (and the rest) to stdout on every control command, from its command thread. Once the 64 KiB pipe fills, that thread blocks for good. IQ keeps streaming at the last applied frequency and `alive()` stays True. The FAST scanner retunes ~8×/s on airband (12 windows per 1.5–3 s), so this hits after about 7–10 min of scanning. From then on every "window" is the same frozen capture, labelled with other windows' channels: false hits on wrong frequencies, or false silence. PRISM click/drag/typed retunes freeze the same way. When the control socket then fills too, `sendall` times out, which is N2. | `poc_stdout.py` with an rtl_tcp stand-in that prints like the real one (`RA-RADIO-poc/bin/rtl_tcp`): retunes 1–3000 match; at 4000/5000/6000 sent, applied stays at 127.925 MHz while IQ still flows and alive=True. | `iqsource.py:110`, `palisade_qt/kit/procs.py:32` |
| N2 | **High** | **Any non-SourceError exception kills the IQ worker with no status.** `IqWorker.run()` is only `try/finally`. `RtlTcpSource._send` (`sendall`) raises raw `BrokenPipeError`/`TimeoutError`, and so do `set_*` in `open()`, `_apply`, `tune_centre` and `_keep_vfo_in_band`. N3's IndexError and a recorder `OSError` (ENOSPC) in `process_block` do the same. The thread exits. `finally` kills rtl_tcp and releases, but no OFF/fault status is emitted and `fault` is not raised. The pages still report running: PRISM `_running()` checks only `held_off`, and PROWL `on_status` never fires again, so SCAN stays green. `ProwlApp._resume_radio` restarts a finished `ScanWorker` only, not a `FastScanWorker`. An operator sees a green scanner that has stopped, which reads as "nothing on air". | `poc_oserror.py`: (1) a peer that stops reading control bytes makes `set_freq` raise `TimeoutError` (not SourceError). (2) A queued retune on a dead socket gives worker running=False, owner None, OFF/fault status emitted=False, fault signal [], errors []. | `palisade_qt/iqworker.py:207-243`, `iqsource.py:173-175`, `palisade_qt/prowl.py` `_resume_radio`, `palisade_qt/prism.py` `_running` |
| N3 | **High** | **Changing the bank during a priority check crashes the FAST scanner.** `_apply(channels=…)` resets the plan but not `_detour` or `_return_win`. The next dwell runs `_resume_listen(*stale_detour)` against the new channel and window lists: IndexError, and then N2. If the indices happen to be in range, it instead resumes "listening" to an unrelated channel of the new bank. Triggers: picking another bank, the custom range, include-ranges, the step, or any priority control (they all call `_apply_bank`) while the scanner sits on a channel with a priority set in another window. | `poc_detour.py`: AIR bank, a 131.55 carrier, priority 121.5 every 1 s. | N4 | **High** | **Max hold does not free a continuous carrier's window.** On max hold the channel goes into `_skip_this_pass`, but that set is cleared whenever window 0 comes round. In a multi-window bank the pass returns to the same window, the strongest carrier wins again, and weaker channels in the same ~1.7 MHz capture are never stopped on. The realistic case is a continuous ATIS in the same capture as tower or approach in the owner's #1 bank: the tower is never heard unless it is locked out by hand. ## Fix bar before re-audit
- N1: rtl_tcp stdout goes to DEVNULL, or a drain thread reads it. Add a test that 10k retunes through a
  stdout-printing stand-in all reach the server.
- N2: `_send` and the setters map `OSError` to `SourceError`. `run()` catches everything else and emits
  FAULT plus OFF. The pages treat a finished IQ worker as stopped (red), and Enter restarts it. Add tests
  for both.
- N3: reset `_detour` and `_return_win` (and `_t_listen` state) on `channels`. Add a test that queues a
  bank change mid-detour.
- N4: max hold must reach the other eligible channels in the same window, and the skip must outlive
  the window-0 wrap for 1-window banks. Tighten the test: a weaker continuous channel in the same
  window must be heard.
- N5–N7 as listed.
